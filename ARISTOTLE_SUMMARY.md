# Summary of changes for run f997bca5-5533-49fb-9401-6bb631d51982
This session ported two more VST test programs to Lean: `progs/queue.c` (VST's `verif_queue.v`) and `progs/queue2.c` (VST's `verif_queue2.v`). As with the earlier VST tests, each program's Clight AST was generated by clightgen (`export/VST/progs/queue.lean`, `queue2.lean`), and separate proof files show that its functions meet VST's specifications. The whole `VST` library builds, there is no `sorry`, and the final `main` proofs depend only on Lean's standard axioms plus the project's two existing model axioms (`CC.externalFunctionsSem`, `CC.inlineAssemblySem`), which all the earlier VST tests also use.

**New library code**
- `export/CCLib/logic/StructField.lean` (imported from `CCLib.lean`): rules for reading and writing a struct field `x->fld` through a pointer, given the field's offset. It also covers writing into freshly `malloc`ed bytes and shows that a `malloc`ed pointer is weakly valid, so the null check `if (!p)` can be decided.

**`queue.c`**, split over five files in `export/VST/progs/`:
- `verif_queue_rep`: how a queue is laid out in memory (`fifo`/`fifo_body` as a list segment), and `surely_malloc` meeting `malloc`'s specification.
- `verif_queue`: `fifo_empty`, `fifo_get`.
- `verif_queue_put`: `fifo_put`.
- `verif_queue_new`: `fifo_new`, `make_elem`.
- `verif_queue_main`: `main` returns `1 + 10`, calling the other functions through their specifications.

**`queue2.c`**, in two files:
- `verif_queue2`: proves `make_elem(data)` (the element's padding is left undefined). The other queue functions in the generated `queue2.c` are identical to `queue.c`'s (shown by `rfl`), so their proofs are reused rather than copied.
- `verif_queue2_main`: `main` returns `1`.
- To make that reuse possible, the queue proofs are now stated for any program whose structs have the queue's layout (`QueueCenv`), instead of for `queue.c` only.

**Two differences from VST**
- The heap model has no fractional permissions, so the queue owns each element outright while it is queued. VST instead splits elements into shares (`Qsh`/`Qsh'`).
- Each `main` proof assumes the program's function names resolve to its own functions (`QueueFuns`), and that `malloc` and `free` are its external functions of those names.
